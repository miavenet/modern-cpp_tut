# Modern C++ concept map

Use this as a route through the lessons. Each question is answered and tested
in the linked lesson; the lab and card are the place to check understanding.

| Module | Route and question |
|---|---|
| 01 Foundations | After reading [Move semantics](modules/01-foundations/lessons/lesson-01-move-semantics.md) and [smart pointers](modules/01-foundations/lessons/lesson-02-smart-pointers.md), ask yourself: who owns this resource, and what state is left after transfer? |
| 01 Foundations | After reading [Auto and lambdas](modules/01-foundations/lessons/lesson-03-auto-lambdas.md) and [enums, clocks, arrays](modules/01-foundations/lessons/lesson-04-enum-chrono-essentials.md), ask yourself: did this declaration copy, borrow, or create a new object? |
| 01 Foundations (LPA) | After the [push_back tail lesson](modules/01-foundations/lessons/lesson-05-lpa-push-back-tail.md) (concept C17), ask yourself: which growth step copies, moves or allocates, and what does the p99.99 see that the mean hides? |
| 02 Type system | After reading [Constant evaluation](modules/02-type-system/lessons/lesson-01-constexpr.md), [concepts](modules/02-type-system/lessons/lesson-02-concepts.md), [traits and folds](modules/02-type-system/lessons/lesson-03-type-traits-fold.md), ask yourself: which conditions are checked while building, and what still needs checking at run time? |
| 02 Type system (LPA) | After [the constinit lens](modules/02-type-system/lessons/lesson-04-lpa-constinit.md) (concept C8), ask yourself: does the first call pay for an initialiser the guard hides? |
| 03 Concurrency | After reading [Thread ownership](modules/03-concurrency/lessons/lesson-01-threads-async.md), [atomics](modules/03-concurrency/lessons/lesson-02-atomics-memory-model.md), [coordination](modules/03-concurrency/lessons/lesson-03-synchronization-primitives.md), [coroutines](modules/03-concurrency/lessons/lesson-04-coroutines.md), ask yourself: what establishes the order between two accesses, and who owns the running work? |
| 03 Concurrency (LPA) | After [spin or sleep at the tail](modules/03-concurrency/lessons/lesson-05-lpa-handoff-tail.md) (concept C14), ask yourself: does the waiter own a fast core, and does the load pair with the release store? |
| 04 Modern library | After reading [Optional, variant, expected](modules/04-stl-modern/lessons/lesson-01-optional-variant-expected.md), [ranges](modules/04-stl-modern/lessons/lesson-02-ranges-views.md), [bindings](modules/04-stl-modern/lessons/lesson-03-structured-bindings-modern-patterns.md), [views and span](modules/04-stl-modern/lessons/lesson-04-string_view-span-ctad.md), ask yourself: does this value own storage, or view storage owned elsewhere? |
| 04 Modern library (LPA) | After [expected vs throw at the tail](modules/04-stl-modern/lessons/lesson-05-lpa-expected-tail.md) (concept C15), ask yourself: at which percentile does a rare error path show up? |
| 05 Memory and performance | After reading [PMR](modules/05-memory-perf/lessons/lesson-01-allocators-pmr.md), [cache layout](modules/05-memory-perf/lessons/lesson-02-cache-soa.md), [compile-time work](modules/05-memory-perf/lessons/lesson-03-compile-time-perf.md), [parallel algorithms](modules/05-memory-perf/lessons/lesson-04-parallel-attributes.md), [pool lab](modules/05-memory-perf/lessons/lesson-05-pool-allocator-lab.md), ask yourself: which allocation request and alignment does the code actually make? |
| 05 Memory and performance (LPA) | After [the pool tail lesson](modules/05-memory-perf/lessons/lesson-06-lpa-pool-tail.md) (concepts C16 and C17), ask yourself: where does a refill reach the heap, and what happens when the slab runs out? |
| 06 Low latency patterns | After reading [SPSC ring](modules/06-hft-patterns/lessons/lesson-01-spsc-lockfree.md), [hot path](modules/06-hft-patterns/lessons/lesson-02-hot-path-design.md), [measurement](modules/06-hft-patterns/lessons/lesson-03-measurement-bypass.md), [prefetch](modules/06-hft-patterns/lessons/lesson-04-prefetching.md), ask yourself: what did this measurement include, and does the change help the measured path? |
| 06 Low latency patterns (LPA) | After [the course histogram](modules/06-hft-patterns/lessons/lesson-03-measurement-bypass.md) (concept C11) and [the tail budget](modules/06-hft-patterns/lessons/lesson-05-lpa-tail-budget.md) (concept C12), ask yourself: are there enough samples beyond the percentile, and was the load open-loop? |
| 07 Architecture and tools | After reading [Modules](modules/07-architecture/lessons/lesson-01-modules.md), [sanitizers](modules/07-architecture/lessons/lesson-02-sanitizers-analysis.md), [benchmarks](modules/07-architecture/lessons/lesson-03-benchmarking-cpp23.md), [CMake](modules/07-architecture/lessons/lesson-04-modern-cmake.md), ask yourself: can another person build and check the behavior with the published commands? |
| 07 Architecture and tools (LPA) | After [map vs flat_map as a distribution](modules/07-architecture/lessons/lesson-05-lpa-map-tail.md) (concept C10), ask yourself: which operation is on my latency path, and what percentile did the benchmark report? |

A short route through the course is in [README.md](README.md). The cards remain
in the lesson files, including lessons you defer for later depth.
